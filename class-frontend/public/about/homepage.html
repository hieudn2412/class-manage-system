What EDU OPS does

Daily operations, connected.

The purpose of EDU OPS is to help learning centers coordinate teaching and administration without scattering important work across spreadsheets, chat threads and personal file folders.

01 / CLASSES

Classes and enrollment

Organize classes, students, teachers, enrollment status and the lifecycle of each center program.

02 / SCHEDULES

Teaching schedules

Plan sessions, assign responsible teachers and keep center-wide and personal timetables aligned.

03 / HOMEWORK

Homework workflows

Publish assignments, select recipients, receive immutable submissions and return reviews or revision requests.

04 / MATERIALS

Learning materials

Share class or session documents through permission-checked private file access for eligible members.

05 / OPERATIONS

Staff and salaries

Support administrative and accounting workflows with role-appropriate teaching activity and salary records.

06 / UPDATES

Notifications and reports

Surface operational changes in-app and help managers follow teaching, submission and review activity.

How it works

From setup to class updates.

EDU OPS keeps the operational journey inside the center's tenant workspace and checks permissions whenever protected data or files are accessed.

Set up the center

An administrator creates accounts, roles, classes and enrollment records.

Plan teaching

Authorized staff arrange schedules, sessions, teachers and learning content.

Teach and respond

Teachers publish work; students submit it and receive review outcomes.

Keep people informed

In-app notifications appear immediately. Gmail delivery is optional.

Disconnect at any time

The Gmail refresh token is encrypted at rest and removed locally when the tenant disconnects. Access tokens remain only in memory while calling the Gmail API.

Privacy and security

Designed around tenant boundaries.

EDU OPS applies role and object-level authorization to operational data and private files. Google access is limited to the smallest scopes needed for email delivery.

Tenant isolation

Requests are resolved inside the authenticated tenant and checked against role, enrollment, class and content state.

Private file delivery

Protected files stay outside the public web root and are delivered through permission-checked endpoints.

Minimal Google access

Only openid, email and gmail.send are requested—never inbox-reading scopes.

User control

Authorized administrators can test, replace or disconnect the tenant's Gmail sender.

Questions and answers

About EDU OPS and Gmail

Is Gmail required to use EDU OPS?

No. Gmail is optional and used only for tenant email notifications. Core class operations and in-app notifications work without it.

Does EDU OPS read the connected inbox?

No. EDU OPS requests gmail.send, not permissions for reading, searching, modifying or deleting mailbox content.

Who can connect Gmail?

Only an authorized tenant administrator can manage the Gmail notification connection for that tenant.

Can access be removed?

Yes. Disconnecting removes local token material. The Gmail owner may also revoke access from Google Account settings.
